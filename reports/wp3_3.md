# WP3.3: controlled GraphGPS PE choices

This experiment measures realized BREC pair distinguishability while holding the
GraphGPS architecture and training protocol fixed. It reuses the repository's
GraphGPS, encoders, BREC evaluator and WP3 analysis/logging infrastructure.

The default matrix is five conditions over seeds 0–4 (25 full runs):

| PE choice | Parameters | Input width on featureless BREC graphs |
|---|---|---:|
| none | constant-one baseline features | 1 |
| RWSE | walk_length=16, steps 1 through 16 | 17 |
| LapPE | k=4, eigen_tol=1e-8 | 5 |
| LapPE | k=8, eigen_tol=1e-8 | 9 |
| LapPE | k=16, eigen_tol=1e-8 | 17 |

GraphGPS supports the no-PE baseline directly. Encodings are appended before its
input projection. All conditions use `configs/models/graphgps.yaml`: four layers,
128 hidden channels, four attention heads, dropout 0.1, ReLU, sum pooling and
trainable GIN epsilon. The implementation fixes multihead global attention and
node-wise layer normalization. `configs/tasks/brec.yaml` fixes batch size 32,
100 maximum epochs, learning rate 0.001 and weight decay 0.00001. The evaluator
keeps its Adam optimizer, stopping rule, 16-dimensional head, RPC test and
reliability controls. No per-condition tuning is performed.

From the repository root with the project environment activated:

```powershell
python scripts/reproduce_wp3_3_graphgps_brec.py --encoding none --seed 0
python scripts/reproduce_wp3_3_graphgps_brec.py --encoding rwse --seed 0
python scripts/reproduce_wp3_3_graphgps_brec.py --encoding lappe --k 8 --seed 0
python scripts/reproduce_wp3_3_graphgps_brec.py --all --seeds 0 1 2 3 4 --resume
python scripts/analyze_wp3_3_graphgps_brec.py
```

`--encoding lappe` without `--k` selects 4, 8 and 16. Other positive `k` values
are supported explicitly. `--threads` defaults to one. `--results-dir` (runner
alias `--output-dir`) defaults to `results/wp3_3/runs`. IDs contain `graphgps`
and, for LapPE, `_kN`, preventing collisions with GIN runs.

Existing results are protected. `--resume` validates completed JSON/configuration
and embeddings before skipping, including completed runs with reliability failures.
Pair-boundary checkpoints now retain completed work and the sequential RNG state;
see [runtime diagnosis and recovery](wp3_3_runtime.md). Orphan embeddings without
a matching resumable checkpoint cause an error. Explicit `--overwrite` evaluates
in a persistent `.replacements/<run_id>` directory before replacing published
artifacts; repeat `--overwrite` to resume that replacement after interruption.
Evaluation failures leave prior outputs intact. Do not run concurrent writers for the same run ID.
Replacing the JSON and NPZ is not a single filesystem transaction.

Raw JSON preserves PE parameters, seed, model/training config, protocol, source
hash, commit, timestamp, runtime, parameter count, environment and validity flags.
Pair records contain IDs, categories, epochs/loss, test/reliability statistics and
distinguished decisions. The existing NPZ embedding output is retained.

Analysis writes `results/wp3_3/analysis/wp3_3_graphgps_by_seed.csv` with `pe_type`,
`k`, `seed`, `distinguished_count`, `total_pairs`, `distinguished_fraction` and
validity, and `wp3_3_graphgps_summary.csv` with seed lists, count mean/sample SD/
min/max and fraction mean/SD. SD uses ddof=1 and is blank with one seed. Use
`--output-dir` for another table location; tables are never overwritten.

Analysis defaults to requiring all 25 complete runs. For a single condition use
`--encoding lappe --k 8 --seeds 0`. `--allow-missing` explicitly permits missing
files, reports them, and retains the exact available seed lists. Incomplete or
inconsistent runs are rejected. Model, attention settings, training, protocol,
source hash and within-condition PE settings must agree across runs. GIN runs
cannot enter this table. Optional cross-model comparison is not implemented;
WP3.1/WP3.2 tables remain separate references.

Counts include only pairs passing both the distinction and reliability rules.
Any reliability failure still invalidates the full benchmark primary metric;
diagnostic counts remain visible with validity flags and failure totals. Do not
report those rows as valid benchmark improvements. LapPE retains zero-padding
when fewer than k positive eigenvectors are available and the existing sign/basis
convention, including ambiguity for repeated eigenvalues. Input projection size
and parameter count necessarily vary with PE width. Seed handling is unchanged;
cross-device or cross-version bitwise reproducibility is not guaranteed.

Unit tests use synthetic full-result fixtures and never train the full benchmark.
The 25 full runs must be executed to obtain measured GraphGPS BREC results;
implementation tests do not establish an expressivity improvement.
