# WP5.4 — Graph perturbation and stability diagnostics

Status: Person B engineering and descriptive diagnostics on small synthetic graphs. This is sensitivity measurement, not evidence of robustness, generalization or theoretical expressivity. Work is isolated to `gnn-expressivity-wp5-4`, branch `analysis/wp5-4-perturbation`. No scientific training is performed.

## Audit and reuse

Reuses WP5.1 `small_graphs`, old-to-new `permutation`/`relabel`, `error_record`, normalized `laplacian_spectrum`, and `native_outputs`. The latter captures GIN's final post-activation/dropout states and GraphGPS's final GPSConv states with temporary hooks removed on exit. Both native forward methods return graph vectors, not node predictions. Existing build_model/build_encoding factories, models, encoders, training code and configurations are unchanged. GIN uses GINConv and graph pooling; GraphGPS uses local GINConv plus multihead attention with node-mode normalization and pooling. Degree is source degree; RWSE appends return probabilities; LapPE selects positive normalized-Laplacian eigenvectors with sign anchors and zero padding, excluding zero modes (including disconnected/isolated components).

## Perturbation contracts

`perturb` accepts one homogeneous, CPU, nonempty simple undirected graph. The input must contain each undirected edge as two unique opposite arcs. It rejects self-loops, duplicates, out-of-range indices, directed adjacency, batches and edge attributes/index schemas: inventing new edge features would require a separately defined scientific policy. Node identities, node count, features and graph attributes are preserved in a clone.

`add` samples absent unordered edges; `remove` samples existing unordered edges; `edits` toggles a specified number of distinct unordered pairs. An edge is toggled at most once, so edits never silently cancel. This mixed policy does not guarantee equal additions and removals or connectivity/degree preservation. Candidates are sorted, then sampled with a local Python RNG. Exact requested count is applied or the original graph is returned with `infeasible`; there is no silent partial edit. Count zero is explicitly `noop`. Full/empty/single-node graphs and all-edge removal are covered in tests. Disconnected inputs are accepted; connectivity changes and isolates are represented by degrees and component counts, without a connectivity constraint.

Metadata records exact added/removed edges, requested/applied counts, seed, before/after node/edge counts, degrees, density, components, degree deltas and density delta. Density is 2m/[n(n-1)], with zero for n=1. Edge ordering may be canonicalized by an applied edit; no edge attributes are silently retained out of alignment.

## Measurement protocol

Fixture families: paths (5 and 8 nodes), C6, K5, regular K3,3, a six-node star, and a disconnected P3 with two isolates. The matrix uses add-one, remove-one, and two mixed edits with seeds 0 and 1. Encodings are constant (`none`), degree, RWSE walk_length=4, and LapPE k=1/2/4. Each pair is tested with actual native GIN and GraphGPS, width 8, two layers, sum pooling, two-dimensional output head, dropout=0 and eval mode. Weights are identical across each original/edited comparison; no independent model initialization is compared. Model creation uses forked Torch RNG; perturbation sampling uses local Python RNG. Tests verify caller RNG preservation.

Recomputed mode runs the same existing encoder on the edited topology. Frozen mode carries the original encoded node features onto the edited topology: this is an adjacency-only ablation, not a claim that frozen degree/RWSE/LapPE is an encoding of the new graph. Both modes retain node identities for intermediate-state alignment. Predictions are untrained graph-output vectors with no calibrated classification interpretation.

Each aligned comparison reports maximum absolute difference, maximum difference divided by the original maximum absolute value, L2/Frobenius difference, and L2 difference divided by original L2. Relative metrics are null for zero reference norm. All metrics are descriptive and no universal stability score is constructed. Numerical controls use atol=rtol=2e-5; they do not assert exact floating-point identities.

## LapPE-specific interpretation

Raw eigenvectors are not assumed aligned. The report retains their differences as explicitly confounded numerical pipeline diagnostics. Such differences and downstream raw-coordinate model/node changes are not geometric instability estimates. Sign-anchor ties, repeated/near-repeated positive eigenvalues, zero-filter proximity, retained rank and truncated eigenvalue blocks are recorded on BOTH graphs. Eigenvalues/gaps may themselves change under the perturbation.

Complete selected eigenspace projectors QQ^T are compared only when both retained ranks match and neither graph cuts a repeated/near-repeated block or has a guarded zero-filter boundary. Gap tolerance is 1e-7; zero-filter guard is min(gap_tol,0.1*eigen_tol), with eigen_tol=1e-8. Rank-changing, truncated, and filter-ambiguous comparisons are explicitly unsupported. A simple-spectrum, matched-rank sign-aligned diagnostic is also provided using signs of corresponding column inner products. It is not used for repeated eigenspaces and does not align or modify the features fed to models. Ordered simple columns can change sharply as spectra approach a crossing; no universal correspondence/stability theorem is claimed.

Tests explicitly rotate a complete repeated eigenvalue block (raw coordinates change, projector remains fixed), flip simple-spectrum column signs, inject near-degeneracy at a boundary and compare unequal retained ranks. All k values can be run because the actual encoder zero-pads; padding is recorded through retained rank rather than misreported as full-rank eigenvectors.

## Controls and statuses

- Identical-graph recomputation and repeated-forward controls must agree numerically.
- A WP5.1 node-permutation control carries existing features and undoes the node relabeling before comparing intermediate states; graph outputs remain directly comparable.
- Addition/removal validity tests confirm actual structural changes, and a native star/degree fixture has nonzero encoding, node-state and graph-output differences for both models.
- Negative alignment controls use nonconstant tagged baseline features, permute topology, deliberately leave features at old positions and require an encoding alignment failure. A native model may erase node distinctions (e.g. complete-graph GIN aggregation), so node-level detection is separately recorded and not universally required. Dedicated native star tests require node-level failure for both models.

Outer row status `pass` indicates a numerical consistency control passed or a negative control detected the expected feature-alignment failure. `diagnostic` means a finite descriptive edge-sensitivity measurement, without an equality assertion. `infeasible` means no legal full perturbation was available; `noop` means no edit requested (utility/tests). Nested spectral `unsupported` indicates no certified complete comparable subspace or no meaningful sign-only alignment. `fail` means an asserted control failed or a comparison was nonfinite/malformed. Inner negative-control metrics intentionally contain `fail`; the outer control row explains their expected status. Unsupported projector metrics do not invalidate the raw numerical pipeline measurement, but restrict its interpretation.

## Mathematical claims and Person A review

Architectural node equivariance and pooled graph invariance concern relabeling an attributed graph consistently; they do not imply invariance to edge edits. Control passes are numerical consistency observations, not mathematical proofs. Edit-sensitivity measurements describe fixed untrained instances, not trained generalization or robustness. Further training or causal hypotheses require separately approved experiments.

Person A must review the admissible graph domain, the edit distribution and connectivity policy, feature admissibility, frozen-feature interpretation, spectral gap/filter thresholds, projector comparability across changed graphs, sign-aligned column correspondence, and task-relevant normalization/tolerances. No expressivity ranking or stability theorem is inferred.

Limitations: small unweighted undirected CPU graphs; no edge-feature policy, batching, heterogeneous graphs, directed edits, trained checkpoints, CUDA, large eigensolvers, exhaustive architectures or significance claims. Model node states are internal hook observations, not a new node-output API. No dependency installation/update, BREC run, training, commit, push or PR is authorized here. Original WP3 files and active GraphGPS checkpoints/results are not accessed or modified.
