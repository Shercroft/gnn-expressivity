# WP5.1 — Person B permutation test harness

Status: engineering verification on tiny synthetic graphs; mathematical interpretation requires Person A review. Work is isolated to `gnn-expressivity-wp5`, branch `analysis/wp5-1-permutation-harness`. No training, dependency changes, commits, or pushes were performed.

## Audit and native contracts

Existing factories `build_model` and `build_encoding` are reused unchanged. GIN performs sum-aggregation GINConv, ReLU/dropout, graph pooling and an optional head. GraphGPS performs input projection, GPSConv local/global attention blocks with node-mode layer normalization, graph pooling and an optional head. Both forward methods return graph outputs, not node outputs. Temporary hooks observe GIN's final dropout output and GraphGPS's final GPSConv output; hooks are removed even on errors. These are observed native intermediate node states, not a new production node-prediction interface.

PyG homogeneous Data stores edge_index as [2,E], features as [N,F], and Batch uses sorted graph membership and ptr. GraphGPS requires sorted membership. Existing permutation tests in test_gin, test_graphgps, test_encodings, test_rwse and test_lappe provided the conventions; the new utility explicitly uses OLD-to-NEW indices rather than inverse gather order.

Degree appends raw source degree. RWSE computes return probabilities in CPU float64, then casts to baseline feature dtype. LapPE uses a symmetric normalized Laplacian, zero isolated-node diagonals, removes all eigenvalues <= eigen_tol, takes k positive eigenvectors, zero-pads, and anchors each sign by its largest-magnitude entry. It does not randomize signs. UID and seeded random features are tied to current array indices.

## Relabeling and checks

`relabel(data,p)` validates a bijection, clones inputs, maps edges through p, and moves node attributes so X_new[p[i]]=X_old[i]. Edge order and corresponding edge attributes stay unchanged. Graph y defaults to graph-level; node labels must be explicitly designated using node_attrs and graph_attrs. Other tensor attributes use PyG node/edge classification, with explicit role overrides for ambiguous attributes. Extra index-bearing fields (including faces) fail explicitly; no attempt is made to reinterpret arbitrary custom index schemas. Non-tensor node attributes are unsupported. Tensor graph attributes whose shape resembles node data should be explicitly listed in graph_attrs.

Batch support is restricted to permutations within each graph, preserving sorted batch membership, ptr and slices. Cross-graph permutations are rejected. Encoders are recomputed per individual graph, never on a disconnected union pretending to be one graph. Tests check native batched outputs against individual graph outputs.

The fixture matrix includes paths with 5 and 8 nodes, a 6-cycle, K5, regular K3,3, a 6-node star and a disconnected 3-path plus two isolates. Every encoding uses identity, reverse, and two locally seeded random permutations. The suite covers constant features (`none`), degree, RWSE length 4, LapPE k=1/2/4, UID, and seeded random features. Both actual native GIN and GraphGPS use width 8, two layers, sum pooling and a two-dimensional output head, fixed weights within comparisons, eval mode and dropout zero. No fresh models are compared to one another. One-layer batched checks provide additional forward coverage. Negative controls deliberately leave features or edges at old array positions and must fail.

Graph invariance compares graph predictions; node equivariance compares observed final node states after undoing the relabeling. Direct structural encoding equivariance compares recomputed encoded features after undoing relabeling. Carrying existing features and recomputing an encoding are separate rows. Carried UID/random features behave as node attributes; recomputing by current index changes their assignment. Tests additionally cover independently regenerated random features with a different encoder seed. A fixed seeded stream is repeatable but does not make regenerated index-tied features equivariant.

## LapPE interpretation

Raw recomputed LapPE columns are diagnostic only. A sign anchor can tie even for a simple eigenvalue; repeated eigenvalues permit orthogonal basis rotation. Near-degeneracy and truncation through a repeated block can change even the selected subspace. Ordinary GIN/GraphGPS are not automatically invariant to these feature-space transformations. Raw model differences from recomputed LapPE are recorded, never repaired by changing features or scientific encodings.

The harness checks QQ^T only when the selected positive eigenspace includes its complete boundary eigenvalue block. A gap <=1e-7 at the k boundary is conservatively unsupported. A near-zero-filter boundary is separately guarded relative to eigen_tol. These thresholds describe this small diagnostic, not a universal spectral stability theorem. Zero-padding does not introduce a false extra eigenspace. A full repeated block's projector can agree despite different basis columns; a synthetic rotation test confirms this distinction. A synthetic near-repeated spectrum tests the boundary guard. Projector agreement alone says nothing about invariance of a model consuming raw columns.

## Reproduction and machine-readable output

Run from this WP5 worktree with the existing compatible interpreter read-only. No environment installation or editable-install change is necessary. The CLI prepends the local src path, limits Torch and BLAS to one CPU thread, uses local RNG generators/forked Torch RNG, performs forward passes only and refuses an existing output directory.

```powershell
& '..\gnn-expressivity\.venv\Scripts\python.exe' -B scripts/check_wp5_permutation.py --output-dir results/wp5_1/permutation_reviewed --permutation-seeds 0 1
```

JSON includes model/encoding configuration, graph family/size, old-to-new permutation and its seed/kind, model initialization seed, test type, maximum absolute error, relative maximum error when reference scale is nonzero, absolute/relative tolerances, status and caveats. Status pass means an asserted numerical contract passed; diagnostic means a finite measurement with no asserted equality; unsupported means the projector comparison has no certified complete boundary block; fail means an asserted contract failed or values were nonfinite/malformed. Standard comparisons use atol=rtol=2e-5. No empirical tolerance asserts exact arithmetic.
